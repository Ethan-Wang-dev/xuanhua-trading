# 玄化交易：项目基线

## 已确认的方向

1. 初期以用户认可的铁书生梅花易数体系为准；教材、版本与案例待用户整理。
2. 梅花易数 Agent 与交易 Agent 分工合作，交易计划进入程序执行与记账。
3. 后续加入大六壬、奇门遁甲，以独立策略竞争，初期不合并投票。
4. 以时辰为分析节奏，以用户所在地真太阳时作为拟定起盘基准；地点、时间换算和调度细则后续确定。
5. 起卦、重新判断和实际成交频率分别定义，不要求每次判断都成交。
6. 项目以娱乐实验为定位，保留决策、依据与盈亏记录，不要求为每次结果补写解释。

## 接下来的实现顺序

### 1. 交易侧梳理与模拟环境

沿 `kernel/engine_analysis.go` → `kernel/engine_prompt.go` → `trader/auto_trader_loop.go` 阅读输入、提示词、输出与执行。建立行情时间戳、字段单位、账户口径、缺失数据和订单状态的明确约定。

优先核查 `kernel/engine_position.go` 中用止损止盈反推入场价格的盈亏比校验，以及 `kernel/schema.go` 的余额与权益描述。调研结论属于静态检查，实施修复前补充针对性验证。

先为项目准备明确隔离的模拟执行路径；不能仅在提示词中写“模拟”而继续调用真实订单适配器。该路径尚未实现。

### 2. 术数知识与 Agent

教材准备好后，建立可追溯的知识库与案例。检查起卦、定位、解卦和应期是否忠于用户认可的方法，再接入交易问题。

术数输入建议包含对象、问题、起卦依据、时间、结论、有效期与来源。该字段集合只是接口设计起点，不是已确定的术数规则。

### 3. 两个 Agent 的协作

明确交易 Agent 能否依据行情否决术数方向、何时允许追问、旧判断何时失效，以及跨时辰持仓如何处理。程序独立处理账户与订单约束。

### 4. 网站与竞争实验

完成玄化交易的界面品牌、实时模拟账户、决策日志与各策略独立记录。现有上游社交链接及图标暂保留，后续统一替换并保留来源说明。

## 尚未确定
